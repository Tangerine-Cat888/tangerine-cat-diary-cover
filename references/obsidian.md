# 朝花夕拾：预览与应用

仅在用户要朝花夕拾／Obsidian 封面时读取。本 Skill 不依赖固定库路径、具体用户配置或预装的图库编号。

## 预览

1. 确认目标库、插件是否存在和实际版本；当前工作目录不自动等于日常库。区分演示库与用户库。
2. 有项目源码时查看封面渲染与样式；没有时通过实际封面编辑器观察模板和控制项。不得假设所有版本都有相同内部接口。
3. 找图前优先确定摄影题签、留白画册、满版影像中的一个模板，经典文字不列入配图选项；名称与行为以当前版本为准。测量实际书架封面宽高、图片槽位、边距、标题区与 object-fit/object-position，不默认所有封面都是3:4，也不把编辑器的大预览当成书架尺寸。
4. 优先在演示库或不持久化的临时预览节点调用实际渲染器；浏览器 API 或 CDP 仅在可用、目标确认的环境下使用，不要求用户专门开启调试端口。不得为预览更改真实授权状态。
5. 不调用保存／更新配置即可完成的预览，应保持不持久化。临时展示结束移除本次创建的 UI 节点、恢复本次改变的视口，不关闭其他窗口或清理用户文件。
6. 使用 HTML/CSS 备用预览时加载本地作品，按实测模板、槽位与书架尺寸排版，标明“模拟书架，尚未在插件核验”。不可自行扩大图片区域或改造模板以美化结果。未经观察的软件操作不能宣称已验收。
7. 把新候选与2～3本内置或现有封面并排展示，标明“视觉参照”和“本轮新增”，保持封面显示尺寸一致；候选统一模板与排版。既检查单张放大图，也检查书架大小下的主体、明暗、留白总量和标题；参照数量不计入用户要求的新候选数。
8. 合理裁切可用于适配，保留全幅对照和参数；关键主体不能因裁切失去意义。不通过给图片加大块留白再套留白模板来强行保存横幅。若成品画面显得过小、暗或空，继续换图或改进预览，不靠主题说明掩盖视觉问题。

## 应用到指定日记本

默认先定模板，再找图与书架对比。在已告知“选定具体封面后自动应用到指定日记本”的步骤中，用户选定包含图片、模板与排版的具体方案，即在该范围内执行；仅选模板而图片未定时不保存。兼容已有图片后补选模板的流程：已告知选择后自动应用时，模板选择完成即可继续。明确应用授权仍有效，不重复询问是否保存，不把任务交回用户手动操作；称赞效果或明确只看预览不构成应用授权。

- 首选目标插件正常编辑／保存入口，保持现有账号、会员和授权设置。不要借此修改授权凭据、激活状态或其他插件。
- 通过库内可用图片选择、图库条目或上传设置封面。内置编号与库附件路径可能是两种不同来源，实际核实后使用；不要把临时绝对路径或 data URL 塞进只接受库路径的配置字段。
- 只修改指定来源／月份的标题、封面与用户同意的裁切／样式；保留阅读位置、篇目排除、其他月份及原始日记正文。
- 确有必要直接编辑配置时，先检查完整 schema 和目标书籍所属集合，在知识库外备份相关配置；避免插件运行期间与内存保存竞争。无法保证不覆盖新状态时，停在可预览方案，不强写整个 data.json。
- 留白画册仍可能使用 object-fit:cover；按已通过书架对比的裁切与留白参数制作附件。禁止临保存时额外加厚留白、缩小画面或改裁切，导致成品偏离用户选定的预览。确需改动时先展示新效果；严重损失主体则回到选图或模板阶段。不把带书名的整张预览重复套入有文字的模板。保留原始文件、来源及适配参数。
- 附件必须确为该图且许可已核实，避免覆盖同名文件。临时文件或网络请求失败不得改变已有封面；应用失败只回滚本次确实改动的字段。
- 回读持久化状态，重新打开书架／封面编辑器，核对图片、标题、位置与选定预览一致；必须再看实际书架大小下的构图、总留白和主体可辨性，不能只证明文件加载成功。文件写入成功而界面无法核验时，分别报告，不宣称显示成功。

同样不默认 push GitHub、打包或公开分享任何日记与配置。
